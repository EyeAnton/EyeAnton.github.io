## Тексты в HTML
Источник текстов — только `site.json`. Текст внутри `[data-i18n]` в HTML — запасной (его видят GitHub, поисковики и превью ссылок); админка при «Опубликовать» (если менялись тексты) сама вписывает туда RU-тексты из site.json (`bakePages` в admin.js, коммиты «Admin: texts in …»). Claude, меняя тексты в site.json в PR, запускает `python3 tools/bake.py` — та же логика (держать две реализации одинаковыми). Тексты в HTML руками не править.
Так же вписывается скрытое: `<style id="baked-hidden">` перед `</head>` прячет `hiddenText`, `navHidden` и выключенные встроенные блоки до первого render (`html:not(.i18n-ready)`) — иначе они мелькают, пока грузится site.json (`hiddenCSS` в admin.js = `hidden_css` в bake.py).

- Блоки: свои (с `type`) удаляются ✕ (есть «Вернуть»), встроенные блоки главной — только скрываются. «+ блок» под блоком вставляет новый после него. На странице проекта блок бывает «половина» (`w: "half"`) — два в ряд, при удалении сетка смыкается. Пустой перевод на сайте подменяется другим языком. Внутри своих блоков любой текст удаляется по наведению «✕ текст» (ключ убирается из блока целиком, RU и EN), текст пункта списка — ещё и «✕ пункт» (карточка, шаг, кнопка); есть «Вернуть». Встроенные тексты главной тоже удаляются «✕ текст» (или ✕ в панели блока): ключ остаётся в `site.text`, а в `site.hiddenText` пишется `"блок:ключ"` — на сайте элемент `hidden` и места не занимает; вернуть — «Вернуть» в панели блока.

Старый адрес `/emotions-club/` переадресует на новую страницу (emotions-club#1); тот репо хранит только ассеты — файлы в нём не переименовывать. Правки кейса — только через админку.

Какие подарки играют в мокапах и какие во вкладках «Подарки: пять шагов» — визуальный выбор в поле блока (тип поля `gifts:all` / `gifts:process`, `giftPicker` в admin.js: превью из gifts.json, порядок ↑↓, ✕). В шагах — только подарки с кадрами из Figma (process.json, 17 шт.; добавлять — `tools/figma/addproc.py` в gift-catalog).
